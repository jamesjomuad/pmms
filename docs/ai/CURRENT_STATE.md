## Project Overview
PMMS (Precision Mechanical Management System) is an internal ERP-style platform for a commercial HVAC contractor. It manages projects from award through closeout, with workflow modules for submittals, RFIs, shop drawings, equipment procurement, punch lists, and change orders. It is a Laravel 13 + Vue 3 (Inertia.js v3) single-codebase application backed by PostgreSQL. Source of truth for data model and architecture: `docs/PMMS-ARCHITECTURE.md` and `docs/PMMS-DATA-MODEL.md`. There is no `README.md`.

## Current Architecture

### Backend
- Laravel 13, PHP 8.5 (runs in lerd Podman container `lerd-php85-fpm`; checks run via `podman exec -w /home/james/Lerd/pmms lerd-php85-fpm composer ...`).
- Controllers in `app/Http/Controllers/`; Form Requests in `app/Http/Requests/`; Models in `app/Models/`. Module models use `#[Fillable]` attribute, `LogsActivity`, `SoftDeletes`, `HasFactory`, and helper methods (e.g. `markReceived`, `markSelected`, `markDelivered`).
- Routes centralized in `routes/web.php` under `projects/{project}/...` (settings/console separately). Nested module routes follow `projects/{project}/equipment/{equipment}/<sub-flow>`.
- Beverage of `Gate::authorize('view'|'update', $project)` on each controller method; `activity()` logging on mutations.

### Frontend
- Vue 3 + Inertia.js v3, `<script setup lang="ts">`. Pages in `resources/js/pages/projects/<module>/...`. Layouts selected in `resources/js/app.ts`.
- Wayfinder generates typed route helpers in `resources/js/routes/projects/...` (auto-regenerated by a watcher when routes change — the generated signatures take a **single** args object `{ project, equipment, ... }`, not positional args).
- shadcn-vue components in `resources/js/components/ui/`; `cn()` from `@/lib/utils`. Icons from `@lucide/vue`. Import ordering enforced by ESLint (external → vue → reka-ui → `@/`).

### Database
- PostgreSQL (lerd `postgres` service). Migrations in `database/migrations/`. Procurement tables added this session: `supplier_quotations`, `purchase_orders`, `equipment_inspections` (each FK → `equipment_items.id`). `equipment_items` keeps its flat `po_status` (`pending|ordered|shipped|delivered|cancelled`) for list-level display.

### Authentication / Authorization
- Sanctum SPA + Fortify. `ProjectPolicy` gates module access; team-level roles gate user/team management.

### APIs / External services / Queues / Caching
- No external APIs. No queued jobs implemented yet. Queue/reverb/redis/soketi/mailpit are configured as lerd services; `queue` + `vite` workers exist.

### Storage

## Important Implementation Details
- **Wayfinder helper call signature**: generated helpers accept a single object of parameters, e.g. `quotationCreate({ project, equipment }).url` — NOT positional args. Passing two positional args fails vue-tsc. The watcher regenerates these files whenever `routes/web.php` changes, so don't hand-write them.
- **shadcn `Select` event value**: `@update:model-value` emits reka-ui's `AcceptableValue` (may be `null`/boolean). Handler params must be typed accordingly (e.g. `(value: AcceptableValue)` via `import type { AcceptableValue } from 'reka-ui'`), never `(value: string)`.
- **Equipment `po_status` transition**: when a PO is created set `equipment.po_status` to lowercase `ordered` to match the UI label enum and `UpdateEquipmentRequest` validation (`pending,ordered,shipped,delivered,cancelled`). Do not write non-enum values (e.g. `Quoted`).
- **Factory conventions**: `protected $model = X::class;` + global `fake()` helper; `User::factory()` / `EquipmentItem::factory()` for FKs.
- **Pipeline order**: lint (Pint) → typecheck (PHPStan) → vue-tsc → eslint → prettier → Pest. Full script: `.agents/verify-pmms.sh` (runs `composer test`, which also clears config).
- **Frontend tooling** must run on host with node at `$HOME/.local/share/fnm/node-versions/v22.23.2/installation/bin`, e.g. `node node_modules/.bin/vue-tsc --noEmit`.
- **No comment/attachment POST routes** exist in `routes/web.php`; the Show pages display `comments`/`attachments` props (seeded/logged) read-only.
- **Procurement nav hub**: the Equipment `Show.vue` gained a "Procurement" tab linking to the three sub-flow Index pages, fed by `equipment.procurement` counts passed from `EquipmentController::show`.
